| Replace an export and every alias | same file `ioplib_hookSameExportEntries`: `CpuSuspendIntr(&oldstate); oldfunc = lib->exports[entry]; for (i = 0; i < table_size; i += 1) if (lib->exports[i] == oldfunc) lib->exports[i] = func; CpuResumeIntr(oldstate);` (same logic as OPL `HookExportEntry`, https://github.com/ps2homebrew/Open-PS2-Loader/blob/b3a2199795fe89ba7e2dd7b843354472dff2c3eb/modules/mcemu/mcemu_sys.c ) | adapted: only entries 25 and 51 are replaced (not every alias). The shipped SIO2MAN 2.4 and 2.7 tables have empty slots (index 4, 27, 28), so a "count until NULL" table size, as in ioplib.c, would stop at 4; in those tables 25 and 51 are the only entries that point at the transfer function (checked with `tools/irxlib.py`). Found because the emulator test used a fake table without holes first and the real tables were then inspected |
| Re-link modules that are already linked | ioplib.c `ioplib_relinkExports`: `for (table = lib->caller; table != NULL; table = table->next) { for (stub = (struct irx_import_stub *)table->stubs; stub->jump != 0; stub++) { stub->jump = 0x08000000 \| (((u32)lib->exports[stub->fno] << 4) >> 6); } }` | copied, plus `FlushIcache()` (loadcore export 4) afterwards, which `ioplib_relinkExports` does not do but the loader does after linking |
| Wrapper that calls the original and works on `sio2_transfer_data_t` | https://github.com/ps2homebrew/Open-PS2-Loader/blob/b3a2199795fe89ba7e2dd7b843354472dff2c3eb/modules/pademu/pademu.c : `pSio2man25[ver] = HookExportEntry(exp, 25, ver ? hookSio2man25_2 : hookSio2man25_1);` "hooking SIO2MAN entry #25 (used by MCMAN and old PADMAN)", "hooking SIO2MAN entry #51 (used by MC2_* modules and PADMAN)"; the wrapper signature is `static void hookSio2man25_1(sio2_transfer_data_t *sd)` and it ends with `sio2proc(td);` | wrapper `bbpad_hook(sio2_transfer_data_t *td)` calls the saved original first, then only reads |
| Late-loaded SIO2MAN | pademu.c `hookRegisterLibraryEntires`: "hooking LOADCORE's RegisterLibraryEntires routine"; `if (!memcmp(lib->name, "sio2man", 8))` | NOT copied for v1. In the Schools/Mega boot ELFs the module names appear in this string order: rtfssiop, sio2man, libsd, sdrdrv, cdvdstm, IOPRP, mcman, mcserv ... padman ... usbd, buzzer (string order, not a traced load order). The worker thread simply retries the lookup every 100 ms for 30 s if SIO2MAN is missing |
| Transfer descriptor layout | https://github.com/ps2dev/ps2sdk/blob/329e2bb43287e16af16c4dde1c614e2662c24468/iop/sio/sio2man/include/sio2man.h `sio2_transfer_data_t { stat6c; port_ctrl1[4]; port_ctrl2[4]; stat70; regdata[16]; stat74; in_size; out_size; u8 *in; u8 *out; in_dma; out_dma; }` | `src/bbpad.c` uses the ps2sdk header directly; the parser in `src/bb_core.c` takes plain arrays, so it is host-testable, and `tests/emu_scenarios.py` builds transfers with the ps2sdk offsets (regdata +0x28, in_size +0x6C, out_size +0x70, in +0x74, out +0x78) |
| How PADMAN fills a pad transfer | https://github.com/ps2dev/ps2sdk/blob/329e2bb43287e16af16c4dde1c614e2662c24468/iop/input/padman/src/padData.c : `return ((ret2 & 0x1FF) << 18) \| ((ret1 & 0x1FF) << 8) \| 0x40;` (out length bits 18..26, in length bits 8..16), `sio2_td.regdata[index] = (reg_data & 0xFFFFFFFC) \| (port & 0x3); sio2_td.regdata[index+1] = 0;`, in/out bytes are packed back to back per regdata entry; `pdGetInSize` = `(PAD_ID_LO(id)*2)+3` | parser walks regdata entries until the 0 terminator, port = bits 0..1, in_len = bits 8..16, out_len = bits 18..26 |
| Pad response framing | OPL pademu.c: `td->in[cmd_size] == 0x01 && (td->in[cmd_size + 1] & 0xF0) == 0x40` identifies a pad command (0x01 address, 0x4x command). The standard response `FF, id, 5A, btn1, btn2 ...` is the PS2 controller protocol; PS2SDK libpad numbering `PAD_SELECT 0x0001 ... PAD_SQUARE 0x8000` | parser accepts address 0x01, command 0x42, response id 0x41/0x53/0x73/0x79 with 0x5A ack |

## 4. What I could not find

No open-source IOP-side *virtual* USB device exists (the first research pass said the same). Everything above is proven for its own purpose (module build, LDD flow, SIO2MAN hook); only the combination is new. The prototype therefore keeps every USBD behaviour that BUZZER.IRX uses identical to the ps2sdk implementation (above) and tests that with a mock client (`tests/test_vusb.c`).
